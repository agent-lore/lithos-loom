Slice A1 of `docs/prd/t2-task-relationship-graphs.md` (read the PRD first — decisions D2, D5, D6 and the Config section are binding; REQUIREMENTS §5.7 is the normative contract and agrees with the PRD).

**Build.** New Foundation modules `graph_cache.py` and `graph_scope.py`; `[lithos-lens.graph]` config (`cache_ttl_s`=30, `max_tasks`=300, `fetch_concurrency`=16, `mini_graph_max_nodes`=40) with `LITHOS_LENS_GRAPH_*` env overrides and the docs↔config env-prefix guard; a pre-fan-out eviction hook on the `EventHub`; `docs/architecture.toml` mapping + `cross_component_edges` budget bump with a reason; isolated-set computation.

- **Cache:** one entry per `task_id` holding its deduped `lithos_task_edge_list(task_id, direction="both")` result, TTL, single-flight; lives on `AppState`. Any consumed task event evicts that task's entry; `lens.refresh` flushes all. A failed `edge_list` is recorded in the scope's `incomplete` set, never cached as empty.
- **Scope (pure over master list + cache):** project scope = the project's tasks per §5B.1, open-only by default, `include_resolved=1` adds the `resolved_since` window; epic scope = `task_children(recursive, include_closed)` + the epic, closed included by default, `include_resolved=0` hides them. Fans out only for misses under the semaphore. Page scope refused above `max_tasks` (ghosts counted).
- **Edge states (both endpoints):** `active` = dependent open ∧ predecessor open|cancelled; `inactive` with `reason: satisfied` (predecessor completed; precedence) or `dependent_resolved`; `unknown` = either endpoint is a ghost whose `task_get` failed. Only `blocks`/`waits_on_gate` are ever satisfied.
- **Ghosts (one hop, leaf-only, never fetch a ghost's edges):** dependency far endpoints that are open, cancelled, or unknown-status are ghosts; a completed out-of-scope predecessor's edge is dropped. Context ghosts are directional and one hop: the *immediate* out-of-set parent and the `discovered_from` source of an included node, never a child/follow-on the resolved filter excluded, never the parent's parent. Open ghosts take title/status from the master open list; only resolved endpoints need `task_get`.
- **Completeness:** result carries `incomplete` and `as_of` = oldest contributing `fetched_at`; an incomplete node is never isolated; a ghost with failed `task_get` is present with `status unknown` and its dependency edges `unknown`.
- **Payload shape** per D3: nodes with `completeness`, dependency edges with `state` (+`reason` on inactive), `roots`, `incomplete`, `as_of`.

**Acceptance (all must have a failing-when-reverted test):** two concurrent project scopes over the fake fetch each task's edges exactly once (call log); a `task.updated` for a node evicts it and the next scope refetches only that task; a page scope of `max_tasks + 1` (ghosts included) is refused with the count; a completed out-of-scope predecessor's edge is absent while a cancelled one is a ghost; a task with only a `parent_child` edge is isolated; a task whose `edge_list` raises lands in `incomplete`, is not isolated, and the scope's `as_of` is its oldest contributing `fetched_at`; a ghost whose `task_get` fails is present with `status unknown` and its dependency edges are `unknown` in both directions; an open child's completed parent outside the node set is a context ghost; an out-of-set `discovered_from` source is a context ghost on the default request; hierarchy fixtures — (a) open epic + one open child + one completed direct child under `include_resolved=0` → scope without the completed child and no `task_get` for it; (b) completed epic + one open child on an open-only project scope → the epic is the child's context ghost and no `task_get` is made for the epic's own parent; an open → completed edge is `inactive` with reason `dependent_resolved`; `completed → open` and `completed → completed` are `satisfied`; the active projection keeps `open→open` and `cancelled→open`.
